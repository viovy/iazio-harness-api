## 1. Autonomous Execution & Headless Resilience

Autonomous headless workflows in multi-slot environments require complete zero-prompt execution guarantees. Prior to STORY-GOV-5274, when an autonomous run was interrupted or left uncommitted changes, subsequent scheduled or resumed jobs failed autonomously:
1. `BindDispatchJobRepo` rejected the authoritative worktree because it had been paused with `ReasonDirty`.
2. The control plane then fell through and inappropriately bound the job to an idle sibling slot, causing multi-slot lock pollution.
3. The running job became blocked or failed to find its dirty worktree branch context.

### 1.1 Non-Interactive Pause Reconciliation
- In `internal/control/engine.go:BindDispatchJobRepo`:
  When a dispatch job explicitly requests or rebinds to an explicit worktree path (`findExplicitHostRepoSlot`), the engine inspects the slot's pause state. If paused due to `ReasonDirty`, `ReasonAdhocASE`, or `ReasonDetached`, it automatically opens the queue (`explicitSlot.Queue = QueueOpen; explicitSlot.Reason = ""`).
- This guarantees that headless story resume passes proceed autonomously without waiting for operator intervention to manually unpause the worktree.

### 1.2 Self-Healing Zombie Lock Eviction
- Dispatched headless jobs (`job_<hex>`) that terminate unexpectedly or migrate between worktrees no longer leave perpetual zombie locks.
- In `internal/control/catalog.go:HeartbeatWithCapabilities`:
  During periodic agent heartbeats, any repository holding an external dispatch lock that is absent from the host's reported active jobs is evaluated via `!e.isExternalDispatchJobActiveLocked(r, r.RunningJobID)`.
- If the job is active on a different slot or no longer active on the host, the stale lock is atomically cleared to `LockIdle`.
- In `internal/httpserver/server.go:enrichRepoWithDispatch`:
  A read-time self-healing pass verifies whether `qJob` exists. If not, any stale `job_<hex>` lock is cleaned immediately upon inspection, preventing downstream automated tooling from observing ghost locks.

### 1.3 Asynchronous Non-Blocking Event Propagation
- Catalog state mutations in `engine.go` broadcast change notifications (`e.notifyRepoLocked`) asynchronously using goroutines and defensive value copies (`cp := *r; go e.OnRepoChange(cp)`).
- This prevents external HTTP webhook listeners or IPC channels from blocking critical control plane dispatch decisions or causing deadlock loops during high-cadence autonomous executions.
