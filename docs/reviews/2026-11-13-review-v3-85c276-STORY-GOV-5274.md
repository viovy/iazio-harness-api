  - Internal card padding enforces standard 12px padding (`padding: const EdgeInsets.all(12)`).
  - Spacing between the icon and text utilizes `const SizedBox(width: 12)`.

## 2. Responsive Layout & Accessibility (a11y) Conformance

### 2.1 RenderFlex & Viewport Bounds
- The card layout uses a `Row` containing an `Icon` and an `Expanded(Column(...))` block.
- Text content is wrapped within `Expanded`, ensuring that long error messages or path strings wrap gracefully without causing `RenderFlex overflowed` horizontal constraint clipping on compact mobile or desktop viewports.

### 2.2 WCAG 2.1 AA Contrast Ratios
- **Container vs Text**:
  - Material 3 `errorContainer` and `onErrorContainer` pairs are mathematically guaranteed by the theme specification to maintain a contrast ratio >= 4.5:1 for normal body text and >= 3:1 for bold title text.
- **Icon Visibility**:
  - Leading `Icons.warning_amber_rounded` in `colorScheme.error` provides non-text contrast >= 3:1 against the surrounding surface.

### 2.3 Assistive Technology & Screen Reader Semantics
- Prior to STORY-GOV-5274, a screen reader announcing the repository detail screen while a harness prompt was executing would read both "Harness Executing Prompt" and immediately follow it with "Worktree Uncommitted Changes: Job scheduling is halted until modified files are committed".
- Suppressing the halted card during `RUNNING_HARNESS` restores coherent accessibility flow:
  - Screen readers focus on the active task execution state.
  - Sibling slots announce their true state (`IDLE`), preventing false multi-lock confusion for assistive technology users.
