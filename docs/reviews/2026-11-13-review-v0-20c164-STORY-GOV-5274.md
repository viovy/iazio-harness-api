# Deep Architecture & Functionality Review: STORY-GOV-5274

**Story Title:** Fix Multi-Slot Duplicate Running Job Attribution and Stale Dirty Pause on Host Worktrees  
**Review Iteration:** scheme_iteration=0 (kind=fixed, profile=architecture_deep)  
**Target Submodules:** `iazio-harness-api`, `iazio-agent`, `iazio-web`, `iazio-infra`, `meta-repo`

## 1. Executive Summary & Context

During multi-slot agent operations on host `debian` (hosting sibling worktrees `/home/romeo/work/meta-repo` and `/home/romeo/work/meta-repo-02`), a running dispatch job (`job_5caae91005a69cef` executing `STORY-GOV-5272`) was simultaneously attributed to **both** worktree slots (`Lock: RUNNING_HARNESS`), while `/home/romeo/work/meta-repo-02` was simultaneously trapped in `Queue: PAUSED` (`ReasonDirty` with the red `Worktree Uncommitted Changes` card).

Forensic investigation revealed five tightly coupled bugs across control-plane binding, heartbeat reconciliation, queue runtime metadata, HTTP API enrichment, process scanning, and UI state precedence:
1. **RC-1 (`BindDispatchJobRepo` fallthrough & substring false matches)**: `BindDispatchJobRepo` relied on `repoMatchesTargetOrSlotFamily` using naive substring checks (`strings.Contains(r.WorktreePath, cleanReq)`), allowing `/home/romeo/work/meta-repo` to falsely match `/home/romeo/work/meta-repo-02`, and falling through to an idle sibling slot when the target slot was marked `QueuePaused`.
2. **RC-2 (`HeartbeatWithCapabilities` sibling lock leak & dead lock persistence)**: Host heartbeat processing set `LockRunning` on the reported worktree without clearing sibling worktrees on the same host that still referenced the same `RunningJobID`, while ignoring external `job_<hex>` IDs when pruning inactive locks.
3. **RC-3 (`UpdateRuntimeMetadata` asymmetry)**: `InMemoryQueue.UpdateRuntimeMetadata` updated `job.Repo` but left `job.WorktreePath` untouched, causing split-brain worktree attribution across dispatch queue lookups.
4. **RC-4 (HTTP server multi-slot cross-talk)**: `findActiveDispatchJobForRepo` matched jobs by host or alias without verifying if another slot on the host was explicitly bound to that job, and `enrichRepoWithDispatch` failed to evict orphaned `job_<hex>` locks.
5. **RC-5 (Agent process detector substring collisions & lease ack omissions)**: `DefaultOSProcessScanner` matched command lines using substring containment (`strings.Contains(commandLine, cleanRP)`), which falsely attributed `meta-repo-02` processes to `meta-repo`; `dispatcher.go` failed to pass the active worktree path in certain lease ack paths; and `iazio-web` failed to suppress the dirty-halt card when a harness job was actively executing.

The commits under review remediate all five root causes and establish end-to-end regression coverage across `iazio-harness-api`, `iazio-agent`, `iazio-web`, and `iazio-infra`.

## 2. Architectural & Design Fitness Review

### 2.1 Control Plane Slot Allocation & Binding (`iazio-harness-api/internal/control/engine.go`)
- **Explicit Slot Matching (`findExplicitHostRepoSlot`)**:
  - Implements strict path-boundary normalization: cleaned path equality (`filepath.Clean(cleanWT) == filepath.Clean(cleanTarget)`), normalized slot matching (`normalizeWorktreePathForSlotMatch`), and numbered slot alias detection (`!strings.Contains(cleanTarget, "/") && family != "" && !strings.EqualFold(cleanTarget, family)`).
  - Guarantees that generic family requests (e.g. `"meta-repo"`) do not hijack explicit numbered slots, while explicit requests for `/home/romeo/work/meta-repo-02` or `meta-repo-02` locate the authoritative slot exclusively.
- **Exclusive Binding & Stale Pause Clearance (`BindDispatchJobRepo`)**:
  - Step 1 checks `explicitSlot := findExplicitHostRepoSlot(hostRepos, cleanWT)`.
  - When an explicit slot is resolved, it binds the job directly to that slot—even if the slot was previously in `QueuePaused`—provided it is not occupied by a different active job.
  - Crucially, it clears transient dirty/adhoc pause states:
    ```go
    if explicitSlot.Queue == QueuePaused && (explicitSlot.Reason == ReasonDirty || explicitSlot.Reason == ReasonAdhocASE || explicitSlot.Reason == ReasonDetached) {
        explicitSlot.Queue = QueueOpen
        explicitSlot.Reason = ""
    }
    ```
    This completely eliminates the race condition where uncommitted files left by an in-flight story branch caused a legitimate resumption job to be rejected and diverted to an idle sibling slot.
  - Sibling eviction loop: sweeps all other repos in the catalog and immediately resets any repo holding `cleanJobID` to `LockIdle` with empty `RunningJobID` and `LockHolder`, notifying listeners via `e.notifyRepoLocked(r)`.
  - Terminates immediately with `return explicitSlot.WorktreePath`, preventing fallthrough to sibling slot family matching.

### 2.2 Heartbeat Synchronization & Dead Lock Eviction (`iazio-harness-api/internal/control/catalog.go`)
- **Host Heartbeat Active Job Reconciliation**:
  - In `HeartbeatWithCapabilities`, when an agent reports an active job with a specific `aj.WorktreePath`, `repoExactPathOrAliasMatch` finds the corresponding repo.
  - It clears `cleanJobID` from all other repos on that host, marks the matching repo `LockRunning`, and clears stale `ReasonDirty` / `ReasonAdhocASE` / `ReasonDetached` pause states.
- **External Dispatch Job Pruning**:
  - Previously, cleanup only checked engine-managed `e.jobs`. Dispatched jobs (`job_<hex>`) were unmanaged in `e.jobs` and survived indefinitely if an agent crashed or re-bound to a different slot.
  - The new logic evaluates `else if len(activeJobs) > 0 && strings.HasPrefix(r.RunningJobID, "job_") && !e.isExternalDispatchJobActiveLocked(r, r.RunningJobID)` to cleanly evict dead external locks.
  - `isExternalDispatchJobActiveLocked` explicitly verifies whether host `h.ActiveJobs` binds `cleanID` to a *different* worktree slot on the host; if so, it returns `false` for the current repo, allowing immediate eviction of the stale sibling lock.

### 2.3 Dispatch Queue Metadata Synchronization (`iazio-harness-api/internal/dispatch/queue.go` & API Handlers)
- In `InMemoryQueue.UpdateRuntimeMetadata`, updating a job's worktree path now atomically synchronizes both `job.Repo = wt` and `job.WorktreePath = wt`.
- In `internal/api/handlers/job_lifecycle.go`, both `AckLease` and `Heartbeat` prioritize `qJob.WorktreePath` ahead of `qJob.Repo`, ensuring consistent slot resolution throughout the entire lifecycle of the dispatch lease.

### 2.4 HTTP Server Projection Isolation (`iazio-harness-api/internal/httpserver/server.go`)
- Added `isDispatchJobBoundToOtherHostRepo`:
  - Evaluates host `ActiveJobs`, queue job candidate paths (`qJob.WorktreePath`, `qJob.Repo`), and other repos on the host holding the same `RunningJobID`.
  - In `findActiveDispatchJobForRepo`, jobs bound to another slot on the same host are skipped.
  - In `enrichRepoWithDispatch`, if `qJob == nil` and the repo currently holds a `job_<hex>` identifier, it automatically resets `repo.Lock = LockIdle`, `repo.RunningJobID = ""`, and `repo.LockHolder = ""`, self-healing stale locks upon read.

### 2.5 Agent Process Detection & Worktree Lease Ack (`iazio-agent`)
- `DefaultOSProcessScanner` (`internal/supervisor/execution_detector.go`):
  - Completely deprecates naive `strings.Contains(commandLine, cleanRP)`.
  - Replaces it with `matchCommandLineRepoPath`, which sorts candidates in descending order of cleaned path length so longer paths (`/home/romeo/work/meta-repo-02`) are tested before shorter prefixes (`/home/romeo/work/meta-repo`).
  - Enforces strict path-boundary delimiters (`isCommandPathStartBoundary` and `isCommandPathEndBoundary`: whitespace, quotes, `=`, `:`, `;`, `,`, `/`, `\`). Suffixes such as `-02` are rejected as path boundaries, preventing `/home/romeo/work/meta-repo` from matching `/home/romeo/work/meta-repo-02`.
- `dispatcher.go`:
  - Encapsulates lease acknowledgement in `ackLeaseWithWorktree`, guaranteeing that `AckLeaseWithWorktree` is called with the resolved `worktreeDir` across all three lease acknowledgement paths (initial reserve, lease renewal retry, and heartbeat re-synchronization).

### 2.6 Frontend UX Precedence (`iazio-web`)
- In `lib/screens/repo_detail_screen.dart`, the error card (`Worktree Uncommitted Changes / Job scheduling is halted`) is now guarded with:
  `&& repo.lock != HarnessLockState.runningHarness && repo.lock != 'RUNNING_HARNESS' && job == null`
- When a coordinated harness execution is in progress, the confusing red banner indicating that scheduling is halted is suppressed, while the informative `Git Status: N modified files` chip remains visible.

## 3. Adversarial Analysis & Silent Failure Check

1. **Path Substring & Sibling Collisions**:
   - *Test Scenario*: Host with slots `/work/meta-repo`, `/work/meta-repo-02`, and `/work/meta-repo-03`.
   - *Analysis*: Because `matchCommandLineRepoPath` sorts candidates descending by path length, `/work/meta-repo-02` (length 20) is evaluated before `/work/meta-repo` (length 17). Suffix `-02` fails `isCommandPathEndBoundary`, completely blocking false matches. In the control plane, `repoExactPathOrAliasMatch` checks exact cleaned path equality and exact alias equality, preventing cross-slot leakage.
2. **Administrative Pause Preservation**:
   - *Test Scenario*: An operator manually pauses a queue (`ReasonUserPaused` or maintenance).
   - *Analysis*: In both `BindDispatchJobRepo` and `HeartbeatWithCapabilities`, pause clearing is strictly conditioned on `(r.Reason == ReasonDirty || r.Reason == ReasonAdhocASE || r.Reason == ReasonDetached)`. Administrative pauses (`ReasonUserPaused`, etc.) remain intact.
3. **Lock & Notification Concurrency**:
   - All mutations in `catalog.go` and `engine.go` execute under `e.mu.Lock()`.
   - Webhook notifications (`e.notifyRepoLocked`) execute asynchronously via goroutines (`go e.OnRepoChange(cp)`) with defensive value copies (`cp := *r`), preventing deadlocks and data races during external dispatch broadcasts.
